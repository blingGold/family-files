## 一、总览

在三份方案已对齐的前提下，本计划把"产品 → 技术 → 原型"落到可执行的工程步骤。

- **技术栈（按技术方案，不再变更）**：

## 二、开工前需拍板的 3 个设计点

方案文档里已有结论的不再讨论，下面 3 点建议在 P1 动手前先定：

1. **附件模型二选一（建议方案 B）**
   技术方案 schema 里附件同时用了两套定位：`ownerType + ownerId` 多态字段，以及 `examId / procedureId / insuranceId` 三个可空外键；且 `AttachmentOwner` 枚举里有 `ENCOUNTER` 但 schema 里没有对应外键。两套并存会让上传/查询/删除逻辑混乱。
   - **方案 A（推荐）**：去掉 `ownerType/ownerId`，保留三个可空外键。附件只允许挂在 检查 / 手术 / 保险 三类下（就诊级图片可直接挂在该次就诊的第一个 Exam 上）。级联删除交给 Prisma，最简单可靠。
   - 方案 B：只用 `ownerType+ownerId`，去掉外键，删除由应用层遍历清理。灵活但代码多。
2. **JWT 策略**：v1 不做 refresh token，access token 有效期先设 **7 天**，前端 localStorage 存储。
3. **提醒提前天数 `leadDays`**：先硬编码全局常量 **30 天**，不做配置页；未读角标 v1 = "到期/逾期条数"，不做已读/未读表。

## 三、阶段划分（P0 → P10）

> 每阶段给出：目标 / 关键任务 / 完成标准 / 依赖。**加粗阶段为 MVP 关键路径**。

### **P0 · 仓库与环境准备（0.5 天）**
- 初始化 monorepo 目录（结构见第四节），`git init`，写好 `.gitignore`（`node_modules`、`dist`、`*.db`、`uploads/`、`.env`）。
- 写 `.env.example`：`DATABASE_URL="file:./dev.db"`、`JWT_SECRET`、`PORT=3000`、`UPLOAD_DIR=./uploads`。
- 约定：前后端统一用 npm；提交前不强制 lint，先跑通再加 ESLint/Prettier。
- **完成标准**：目录结构就位，`git log` 有首个提交，`.env.example` 可被后端读取。

### **P1 · 后端骨架 + 数据库落地（1 天）**
- `nest new backend`，装 `@prisma/client prisma @nestjs/jwt bcrypt` 等。
- 把技术方案里的 Prisma schema 落盘，**按第二节第 1 点修订 Attachment 模型**。
- `prisma migrate dev --name init` 生成首迁移；写 `prisma/seed.ts` 创建一个 admin 账号。
- 配置 `ConfigModule`、全局全局前缀 `/api`、CORS（开发期允许 Vite 端口）。
- **完成标准**：`npm run start:dev` 起得来；`/api/health` 返回 200；admin 可在 SQLite 里查到；`prisma studio` 能看到全部表。

### **P2 · 鉴权 + 用户/权限守卫（1 天）**
- 后端：`POST /api/auth/login`（校验 bcrypt → 签 JWT）；`JwtAuthGuard` 全局守卫；写 `PatientAccessGuard`：非 admin 请求病人相关资源时，校验 `user_patient_access` 存在，否则 403。
- 后端：`users` 模块 CRUD + `POST /api/users/:id/access`（覆盖式授权）。
- 前端：Vite + React Router 初始化，封装 axios（带 Bearer、401 跳登录）；Zustand 存当前用户；P1 登录页；路由守卫（未登录跳 `/login`）。
- **完成标准**：admin 能登录拿 token；普通用户 token 请求未授权病人 → 403；前端登录态刷新后仍在。

### **P3 · 病人 + 疾病主干（1.5 天）**
- 后端：`GET/POST /api/patients`、`GET/PUT /api/patients/:id`（详情聚合：基础信息 + 进行中疾病 + 保险概览）；`GET/POST /api/patients/:id/conditions`、`GET/PUT /api/conditions/:id`。
- 前端：底部 4 Tab 骨架（首页/提醒/保险/我的）；P2 首页——顶部病人切换下拉（只列当前用户可见病人）、基础信息卡、疾病汇总卡列表、保险概览占位。
- **完成标准**：admin 能新建家庭成员和疾病；普通用户切换病人只看得到被授权的人；首页卡片字段与原型 P2 对齐。

### **P4 · 就诊 + 子记录 + 疾病时间轴（2 天）★ MVP 核心**
- 后端：`POST /api/conditions/:id/encounters` 支持一次性嵌套 exams/medications/procedures；`GET /api/conditions/:id/timeline` 把就诊及其子记录、复查节点合并按日期倒序返回。
- 前端：P3 疾病时间轴（竖向时间轴，就诊节点可展开看检查/用药/手术）；P4 新建就诊表单（动态增删检查/用药/手术子表）。
- **完成标准**：能完整跑通"建疾病 → 建就诊（含检查结果与医嘱）→ 返回时间轴看到该次就诊"；时间轴按日期正确倒序，手术节点图标区分。

### P5 · 附件上传（1 天，可与 P4 尾段并行）
- 后端：`POST /api/attachments`（multipart，限制图片 MIME 与大小 ≤ 10MB）；`GET /api/attachments/:id` 经鉴权后以流返回（不允许静态目录直出）；删除时同时删 DB 记录与磁盘文件。
- 前端：P4 表单里"拍照/相册"上传；P3 时间轴里报告图缩略图 + 点击全屏预览。
- **完成标准**：手机浏览器调起相机拍报告可上传；未登录访问附件 URL 返回 401；删除就诊后对应图片文件被清理。

### **P6 · 复查提醒闭环（1.5 天）★ MVP 闭环**
- 后端：`POST /api/conditions/:id/followups`；`GET /api/followups?scope=&status=`（`dueDate <= now + leadDays`，逾期置顶）；`POST /api/followups/:id/complete`——完成时若 `recurring=true` 自动 `completedDate + intervalMonths` 生成下一条 PENDING；`PUT /api/followups/:id` 用于推迟/改期/取消。
- 前端：P4 底部"设置下次复查"区块（一次性/周期性切换）；P5 提醒中心（全部/逾期/本月/已完成筛选，[去复查] 带 diseaseId 跳新建就诊并预填）；首页 Tab 角标 = 待到期条数。
- **完成标准**：就诊时勾选"每 6 个月复查"→ 提醒中心出现该项 → 点完成后自动生成 6 个月后的下一条；一次性复查完成后不再出现。

### P7 · 保险管理（1 天）
- 后端：`GET/POST /api/patients/:id/insurances`、`PUT /api/insurances/:id`；保单附件走 P5 附件接口。
- 前端：P6 保险页（医保/商业险分组、到期高亮）；P3 疾病详情底部"该病人可用保险"反向提示。
- **完成标准**：能录入职工医保与一张重疾险；临近到期（≤30 天）在保险列表黄标提示。

### P8 · 用户/权限管理 UI + "我的"（0.5 天）
- 前端：P7 用户管理列表（仅 admin 可见入口）、编辑授权弹窗（勾选可见病人）、修改密码、数据备份导出入口。
- 后端：备份导出 = 打包当前 SQLite 文件 + `uploads/` 为 zip 流式下载。
- **完成标准**：admin 给"妈妈"账号勾选可见病人后，妈妈登录只看到这几个人；导出 zip 可下载。

### P9 · 联调打磨与移动端适配（1 天）
- 全部空态、加载态、错误态；375px 宽度真机/模拟器走查 7 个页面；表单校验与 toast；底部 Tab 角标实时刷新（用 TanStack Query 自动 invalidate）。
- **完成标准**：iPhone SE 宽度下无横向滚动；所有必填项有校验；提交失败有可读错误。

### P10 · 部署（0.5 天）
- 写 `frontend/Dockerfile`（多阶段：构建 → nginx 静态托管，反代 `/api` 到后端）；`backend/Dockerfile`（node:20-alpine，跑 `prisma migrate deploy && node dist/main`）。
- `docker-compose.yml`：两个服务 + 两个卷（`pgdata` 改名 `sqlite_data` 挂 `backend/prisma/*.db`、`uploads` 挂附件目录）。
- 写 README：一键 `docker compose up -d`；提示生产前配 HTTPS 与定期备份。
- **完成标准**：干净机器（装好 Docker）`docker compose up` 后手机浏览器可访问并完成登录。

## 五、关键实现要点（避免返工）

- **权限守卫要集中**：在 `PatientAccessGuard` 里一次性把"当前 user → 可见 patientId 集合"解析出来，service 层所有查询都带 `patientId IN (...)` 过滤；admin 直接放行。不要在每个 controller 里零散判断。
- **时间轴接口**：后端一次返回 `{ encounters: [...], followUps: [...] }`，前端按日期 merge 成一条流；不要前端多次请求再拼。
- **复查完成闭环**：`/followups/:id/complete` 是一个**写操作事务**——把当前 FollowUp 置 DONE、回填 completedEncounterId、若周期性则在同一事务里 create 下一条 PENDING，避免半途失败产生孤儿提醒。
- **附件鉴权**：`uploads/` 绝不挂成静态资源路由；下载接口必须过 JWT 守卫，防止病历图片被未授权 URL 遍历。
- **前端缓存键约定**：`['patient', id]`、`['condition', id, 'timeline']`、`['followups', scope]`，写操作后按键 invalidate，保证角标与列表实时刷新。

## 六、MVP 验收清单（Definition of Done）

- [ ] admin 账号登录后可新建家庭成员、新建普通用户并勾选授权病人。
- [ ] 普通用户登录后，首页/切换下拉只出现被授权的病人；直接改 URL 访问未授权病人 → 403。
- [ ] 为某病人新建疾病 → 新建就诊（含至少一条检查结果 + 一张报告照片）→ 时间轴可见。
- [ ] 就诊时勾选"周期性每 6 个月复查" → 提醒中心出现该项 → 标记完成后自动生成下一条。
- [ ] 一次性复查完成后从提醒列表消失。
- [ ] 保险按人录入，疾病详情页能反向列出该病人可用保险。
- [ ] 375px 宽度下无横向滚动，拍照上传可在手机浏览器调起相机。
- [ ] 干净环境 `docker compose up -d` 后手机浏览器可登录使用。

## 七、风险与备注

| 风险 / 不确定项 | 影响 | 应对 |
|---|---|---|
| 本机未装 Docker | P10 无法本地验证部署 | 开发期用 `npm run dev` 双进程跑；P10 前再装 Docker Desktop |
| SQLite 并发写 | 多人同时写同一档案可能锁库 | 单家庭场景并发极低；真出现再按技术方案预留路径切 PostgreSQL（只改 datasource） |
| 报告拍照 OCR | v1 不做文字识别，全靠手填 | 附件图片留档即可；后续可加 OCR 作为增强，不影响数据模型 |
| 病历数据敏感 | 泄露后果严重 | 密码 bcrypt；HTTPS 部署；SQLite 文件 + uploads 纳入定期备份；不接外部通知渠道 |
| 原型里"数据备份导出" | 需在 P8 实现 | 直接打包 `.db` + `uploads/` 为 zip，最简单可靠 |
